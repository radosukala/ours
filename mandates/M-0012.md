# M-0012 — Deploy our.one

**Status:** DRAFT, under [`D-0013`](../decisions/D-0013.md) §G, amended by
[`D-0014`](../decisions/D-0014.md) §D, [`D-0015`](../decisions/D-0015.md) §I,
[`D-0016`](../decisions/D-0016.md) §M, [`D-0018`](../decisions/D-0018.md) §F,
[`D-0019`](../decisions/D-0019.md) §I, [`D-0020`](../decisions/D-0020.md) §G
and [`D-0021`](../decisions/D-0021.md) §G.
It is adopted by the founder's
explicit go in chat, once its preconditions hold. Until then, nothing is
deployed.
**Class:** DEPLOY
**Machine projection:** [`M-0012.yaml`](./M-0012.yaml)

## What it does

It publishes the build verified under M-0011, M-0013, M-0014, M-0015,
M-0016, M-0017 or M-0018, as `our.one`:

- Vercel, with Neon as the database and Resend for email;
- the database migrated, and the founder's own account created as the one
  administrator, by Vercel's production build (M-0018, D-0021 §D);
- a proof over HTTP that what runs is what was verified.

Seats stay closed until the founder opens them.

## What the founder does first

No agent handles a secret, so these steps are the founder's:

1. **The written designation** of Ctrl AI's representative in the EU, signed
   (GDPR Article 27(1); D-0014 §B). D-0014 settles the contact email
   (`privacy@ctrlai.com`) and the choice of a representative.
2. **Vercel:** a project linked to `github.com/radosukala/ours`, with root
   directory `apps/web`, and no overrides for its build, install or output
   commands: `apps/web/vercel.json` sets the build command and the
   functions' region, Frankfurt, and Vercel picks pnpm from the lockfile
   (D-0021 §D, §J). Keep *"Enable access to System Environment Variables"*
   on: the release gate reads them.
3. **Neon:** a database in an EU region. Its connection URL goes into
   Vercel as `DATABASE_URL`, for production only, so that no preview build
   can reach it. If Neon is added through Vercel's integration, every
   variable it adds is for production only too.
4. **Resend:** the `our.one` domain verified, by adding its DNS records.
5. **In Vercel's environment settings,** enter:
   - `SESSION_SECRET` and `CRON_SECRET`;
   - `RESEND_API_KEY`, `MAIL_FROM` and `MAIL_TRANSPORT=resend`;
   - `DATA_CONTROLLER=Ctrl AI, Inc.`,
     `DATA_CONTROLLER_EMAIL=privacy@ctrlai.com` and
     `DATA_CONTROLLER_REPRESENTATIVE=Rado Sukala`;
   - `CLIENT_IP_HEADER=x-vercel-forwarded-for`;
   - `APP_URL=https://our.one`;
   - `FOUNDER_EMAIL`, `FOUNDER_HANDLE` and `FOUNDER_NAME`, for the founder's
     own account, which the production build creates (D-0021 §D);
   - at the go, `OURS_RELEASE`: the verified commit, the only one whose
     production build may touch the database (D-0021 §D).
6. **The domain:** move ONE to `oneburger.cz`, then point `our.one` at
   Vercel. In Settings → Environments → Production:
   - turn off the automatic assignment of custom production domains, so
     that our.one serves only a deployment the founder promotes (D-0021
     §D);
   - set the production branch to `release`, which only a deploy moves.
     Pushes to `main` then build previews, which hold no production
     setting. Keep Deployment Protection on for previews (D-0021 §J).
7. **The 7% sentence:** confirm that the court's opinion says what the
   feed's page, `/feed`, cites (D-0015 §E; D-0020 §B). The passage and its
   page are quoted there.
8. **The common agreement:** approve the exact wording of `/agreement`
   (D-0018 §B).
9. **Where proposals go:** choose the address and set `PROPOSALS_EMAIL` in
   Vercel (D-0018 §D).
10. **The build kit and the front door:** approve rules version 0 and the
    exact wording of `/build` and `build.md` (D-0019 §I), and of the front
    door, `/feed`, `/projects` and `/maintainers`, with the new line for a
    coding agent (D-0020 §G). In Vercel, keep files outside the root
    directory available to the build: `/build.md` and `/kit/` are read from
    `kit/` when the site is built.
11. **The hosting lines:** `/privacy` and `/power`, and the control record
    behind `/power`, say *"our.one is not deployed"*. The build that is
    deployed must say what is true once it runs, so a BUILD change makes
    them follow the running server first, or the deploy waits (D-0020 §G).
    M-0018 is that change: this holds once it is verified (D-0021 §C).
12. **The Vercel plan:** one whose terms the founder has checked for a
    service run by a company. Its price goes in the ledger in a later
    commit, verified the same way, before the public launch (D-0021 §J).
13. **`apps/web/.env.local`** holds no real key (D-0021 §F, §J).

## Then, on the founder's go

The founder names the verified commit in `OURS_RELEASE`, and `release` is
moved to it: by the founder, or by the agent on the go. That production
build applies the migrations and creates the founder's administrator
account from the founder's own settings (M-0018). The founder promotes it,
and our.one serves it. No agent holds the database's address or any key.

After the deploy, the founder records the production infrastructure in
`authority/FOUNDING-AUTHORITY.md` §4, by a record (D-0021 §J).

The agent:

- checks every page and the health endpoint over HTTP;
- takes screenshots;
- writes the release receipt.

The founder signs in at `/signin`, by email, and opens seats when the
launch starts.
