# M-0000 — Build the deterministic kernel

**Status:** DRAFT — awaiting founder adoption
**Class:** BUILD
**Authorizing decision:** [`D-0000`](../decisions/D-0000.md)
**Machine projection:** [`M-0000.yaml`](./M-0000.yaml)

## The seed's privileged status

M-0000 is the manual seed. It was written by hand, not compiled by a kernel,
because the kernel it authorizes does not exist yet. This is the standard way
a compiler is bootstrapped, and the privilege is stated rather than hidden.

Every mandate after this one — beginning with M-0001 — must be validated by
the kernel M-0000 produces. If M-0000's own output cannot validate M-0001,
the bootstrap has failed and must be redone, not worked around.

## Objective

Build a deterministic library and CLI that, given a repository of authority
records, answers one question correctly and repeatably:

> **Is this mandate authorized, by whom, and within what bounds?**

And, when the answer is no, says exactly which rule refused and why.

## Human outcome

A stranger with a checkout, no account, and no network can run one command
and see for themselves that an invalid authority chain is rejected — and read
the reason in a sentence they understand.

## Adopted constraints

- No network access in the kernel. Validation is pure and offline.
- No database. Git and the filesystem are the record.
- No deployment of any kind.
- No claim that members exist or that anything is member-owned.
- Every rule reports its enforcement class. A `DECLARED` rule is never
  counted as enforced.
- Denial paths are tested at least as thoroughly as the success path.

## Hypotheses

Recorded so they can be falsified rather than assumed:

1. Five materially different invalid chains can each be rejected for a
   specific, correct, human-readable reason.
2. A non-technical reader can understand a refusal without reading the code.
3. The record schemas survive M-0001 without a breaking change.

## Acceptance tests

1. A valid chain — Founding Authority → Constitution → D-0000 → M-0000 —
   validates, and the CLI exits `0`.
2. At least five materially invalid chains each fail, each for a distinct and
   correct named reason:
   - an agent attempts to issue a decision;
   - a mandate cites a decision that does not exist;
   - a mandate's authority window has expired;
   - a mandate claims a class its decision does not authorize;
   - a mandate writes to a path its own scope denies;
   - a source's recorded digest does not match its bytes;
   - a destructive change declares no irreversible residue.
3. Every constitutional article referenced by a check reports its enforcement
   class, and the summary never states a bare count of "checks passed".
4. The verifier runs against an exported bundle with no repository access.
5. `pnpm typecheck` and `pnpm test` pass.

## Evidence required

- test output naming each denial and its reason;
- a build receipt recording agent, model, scope touched, and failures;
- a truthful statement of what is enforced versus declared.

## Stop conditions

Stop and escalate rather than proceeding if:

- a check cannot be made deterministic;
- the schema begins growing into a general policy language;
- any acceptance test would require weakening a constitutional article;
- implementing a rule requires inventing a fact marked `[CONFIRM]`.

## Rollback

Additive. No existing system is modified; reversal is deletion of the new
repository. **Irreversible residue: none.** No data is written outside this
repository, no message is sent, no external state changes.
