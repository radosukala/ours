# M-0008 — A class line cannot name a check that does not exist

**Status:** DRAFT — awaiting founder adoption, after `D-0009`
**Class:** BUILD
**Authorizing decision:** [`D-0009`](../decisions/D-0009.md)
**Machine projection:** [`M-0008.yaml`](./M-0008.yaml)

## Objective

Three things, all small:

1. **The class-line test.** A conformance test that parses every article
   of the constitution, reads each class line's *kernel: …* and
   rule-name references, and fails if a named rule is carried by no finding
   the kernel produces for the founding chain — so that a class line
   claiming a check that does not exist fails the suite the day it is
   written.
2. **`ours articles`.** A CLI report that prints, for the institution's
   root or a community's, every article of the governing document with its
   declared class beside the class and outcome the kernel actually
   produced on the last check, with no combined total.
3. **One parser.** `apps/proof` imports the kernel's `parseArticles`
   instead of keeping its own copy, which `M-0006` had to duplicate because
   `apps/**` was denied to it.

## Human outcome

A reader who doubts a class line can run one command and see, article by
article, what the constitution says holds and what the kernel actually
held on the last run — and the next time the two diverge, the suite says
so before a person has to.

The test reads the constitution; it may not edit it. The amendment is
`D-0009`'s, in its adopting commit.

## Acceptance tests

1. The class-line test passes against the constitution as amended by
   `D-0009`, and fails — shown by a variant — when a class line names a
   rule no finding carries.
2. `pnpm ours articles` prints every article with its declared and actual
   class, for the institution's root and for `communities/dilna-fixture`.
3. `apps/proof` builds with the kernel's parser and its page tests pass
   unchanged.
4. `pnpm typecheck` and `pnpm test` pass; `pnpm ours check M-0008 --changed`
   authorises the finished working tree.

## Stop conditions
