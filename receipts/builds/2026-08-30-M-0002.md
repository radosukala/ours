## The violation this mandate exists to correct

While building `M-0001`, the implementation wrote
`receipts/builds/2026-08-30-M-0001.md`. **`M-0001` denies `receipts/**`.**

Two failures, and the second is the serious one.

**The mandate contradicted itself.** Its evidence section required a build
receipt; its scope denied the only directory one can live in. That guarantees
either a violation or a missing receipt. There was no correct action available
to the implementer.

**Nothing objected.** `R-SCOPE` evaluates `changedPaths`. No caller ever
supplied any. The trace reported, accurately, *"Scope is coherent. No changed
paths were supplied, so nothing was checked against it"* — and the agent
building it, and the receipt it wrote, both treated that as a pass.

The honest description of `R-SCOPE` before today was `DECLARED`, not
`ENFORCED`. It existed, ran, reported truthfully, and decided nothing, while
its `ENFORCED` tag invited a reader to count it as protection. That is the
shape of every future failure in a system like this one, and it was found by
accident rather than by a check.

## What changed

1. **`R-SCOPE` reports `NOT_MACHINE_DECIDABLE` when no paths are supplied**,
   with the command that would decide it. An unrun check can no longer read
   as a clean one.
2. **`ours check --changed`** reads `git diff --name-only HEAD` *and*
   `git ls-files --others --exclude-standard`. The untracked half matters:
   the M-0001 violation created a new file, which `git diff` alone does not
   report.
3. **`receipts/builds/**` is allowed** wherever a build receipt is required,
   and a test now enforces that pairing for every mandate.
4. The founding authority records the operator's stated facts, in §4.1.

## A sequencing finding

Running `--changed` for the first time immediately refused:
`decisions/D-0002.md is denied by decisions/**`.

That refusal was correct about the paths and wrong about the situation. The
working tree contained both the records that *grant* authority and the work
done *under* it, and a mandate cannot have produced the decision that
authorises it.

The resolution is procedural, not a code change: **a decision and its mandate
are committed before the implementation begins.** They were, in commit
`5dca1ed`, and the check then evaluated the three implementation paths alone
and passed.

This is how it should have worked from the start. Writing the mandate and the
code in one uncommitted blob makes the mandate unfalsifiable — there is no
baseline to measure the work against.

## Amendment — the registered office was wrong

**Added 30 August 2026, under the same mandate.**

The registered office recorded above from the founder's statement — 800 North
King Street, Wilmington, DE 19801 — was **incorrect**. The founder
subsequently supplied Article II of the Certificate of Incorporation:

```text
REGISTERED OFFICE   131 Continental Dr, Suite 305
                    Newark, DE 19713, New Castle County
REGISTERED AGENT    Legalinc Corporate Services, Inc.
```

The certificate governs. §4.1 of the founding authority now carries these
values, and the superseded entry is retained beside them rather than
overwritten.

### Why this is the most useful thing in this receipt

The fact was recorded as *stated, unverified* and was contradicted by the
governing document roughly twenty minutes later. Had it been written as fact —
which is what a system without an evidence column does by default — this
declaration would now assert something false about the entity it names, and
nothing in the repository would ever have questioned it.

`R-CHECKABLE-CLAIM` is classed `INTERPRETED` precisely because no machine can
do this. No test could have caught it. What caught it was marking the claim's
provenance honestly and leaving it visible until a better source arrived.

### Evidence level, precisely

These values are **quoted from a certificate, not read from a filing.** That
is better evidence than a recollection and short of verification. Closing it
means retrieving the entity record from the Delaware Division of Corporations
and citing its file number, which no one has done.

Still open: file number, incorporation date, officers, directors, ownership,
the founder's relationship to the entity, and whether it holds any asset of
this project.
