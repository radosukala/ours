## Failures during the build

1. **The contract check refused the conforming fixture.** The first
   version treated `layer.write("booking", { … })`'s record as a field
   list, found it was not an array of string literals, and refused it as
   undecidable. The test caught it, not inspection. Fixed by reading a
   write's record as an object literal and checking its keys against the
   declared fields — which is the better check, and a computed or spread
   key is still refused.
2. **Two batches of fixture files were written from the wrong working
   directory.** The shell's directory had moved into the fixture; one
   batch landed correctly by coincidence, the other did not land at all.
   Caught by listing the tree before continuing; rewritten with absolute
   paths. No file was written outside the mandate's scope.
3. **The first typecheck failed** on three references to a renamed
   variable in the CLI's export and verify commands. Fixed.

## Amendment — after the independent verification, 8 September 2026, later

The verification — [`2026-09-08-M-0006.verification.md`](../conformance/2026-09-08-M-0006.verification.md),
by an independent agent: the same model, a different context, no access to
the builder's conversation — found sixteen mutations the gate accepted and
should have refused, one refusal made against the adopted specification's
own example, refusals the specification listed that no test exercised, two
numbers wrong in these receipts, and one change in an adopting commit made
outside any mandate's scope. All of it was right. What changed, under this
mandate, in the commit that carries this amendment:

**The static contract check was rebuilt to refuse by default.** Its first
form recognised one syntactic shape and passed a tree in which the client
was aliased with "0 client call(s), every one inside the contract" — a
check that saw nothing. Now: the identifier `layer` may appear only as the
receiver of a direct `read`, `write`, or `disclose` call, or as a
declaration name, and any other reference is refused as undecidable; the
reserved method names on any other receiver, or bare, are refused; a read
requires a literal field list, a write an object literal of literal keys, a
disclose a literal list; imports are an allowlist — the application's own
files, the client package, and the package roots the contract declares
under `dependencies` — and a built-in module in any form or subpath, an
I/O package by any subpath, a dynamic `import()`, `import = require()`, and
`import.meta` are refused; the names that reach around the client —
`fetch`, `require`, `createRequire`, `eval`, `Function`, `process`,
`globalThis`, `window`, `self`, and the rest of the list in `spec/SPEC.md`
§4 — are refused wherever they appear; every file the runtime could
execute is read, and the pass message says how many were read, how many
were not, and what is still not checked. Closes S1, S2, S5, S6, S7, S8,
S10, S11, S12. For S9, the specification's §5 example was the thing that
disagreed with the check; the specification was amended — a write carries
an object literal — rather than the check weakened, and the founder's
approval of the amended §4–§5 is pending.

**The records checks.** F8: tally components, ballots, and the eligible
count must be non-negative integers. F13: every decision in the root is
checked, not only the one the mandate cites — reported as
`C-DECISIONS/root` and `C-PARTICIPATION/root` — and a charter must name the
`CHARTER`-class decision that adopted it (`S-CHARTER-ADOPTED`). F14: the
decision a pin names must record `pins: true`; any adopted decision id no
longer suffices. F15: a draft specification is refused by `S-TOOL-NAMED`
and by `admit`. F16: `admit` reads the charter's status and refuses a

## Second amendment — after the re-verification at `f450774`, 8 September 2026, later still

A second independent agent, fresh context, re-ran every item the first
verification marked FAILED: **all sixteen closed**, each refused by the
right article with the cause named. It then tried new forms against the
rebuilt contract check and found four the check accepted:

- `([]).constructor.constructor("return fetch")()` — the walk to the
  Function constructor from any value; `constructor` was not a refused
  name;
- `global["fetch"](…)` — Node's `global` was absent from the refused list,
  which had `globalThis`, `window`, and `self`, and a string subscript never
  became the identifier `fetch`;
- `Reflect.get(global, "fetch")` — the same absence, reached another way;
- a source file behind a symbolic link the walk never entered, against
  the words "every file the runtime could execute is read".

It also found the amendment above claimed "nine files" where the fixture
has eight, and that "the names that reach around the client are refused
wherever they appear" held for the enumerated names and not for outbound
access as a whole. Both right.

**What changed, in the commit that carries this amendment.** A list of
forbidden names cannot be complete, so the check no longer relies on one.
It binds the source with the TypeScript binder and no library, so that
every identifier in a value position either resolves to something the
application declared or imported, or is a global — and a global is refused
unless it is on a short allowlist of values that cannot reach outside the
process: the ECMAScript built-ins, timers, and `console`. `Function`,
`Reflect`, `Proxy`, `WebAssembly`, `global`, `globalThis`, `process`,
`fetch`, and any name nobody thought of are refused because they are not
allowed, not because they are listed. The doors that need no global are
refused by name, because they are few and fixed: `.constructor`,
`.prototype`, `__proto__`, `.callee`, `.caller` on any receiver, by dot or
by bracket; `arguments`; top-level `this`; a `with` statement. Relative
imports may name a source or JSON file and nothing else, so a native addon
is refused. A symbolic link anywhere in the tree is refused, because it can
point outside what is read. `spec/SPEC.md` §4–§5 say so; the founder's
approval of the amended text is pending, as before.

**Claims restated.** Not "the names that reach around the client are
refused wherever they appear" but: *every name the application reaches is
declared, imported, or on the allowlist, or the implementation is
refused.* Not "every file the runtime could execute is read" but: *every
regular file with an executable extension is read, and a symbolic link is
refused rather than followed.* What is still not checked is unchanged and
still in every message: what a declared dependency does inside itself, and
anything at runtime.

**Tests.** Eight more, one per door and one for an ordinary implementation
using the allowed globals, so that the allowlist is not so narrow that a
booking tool cannot be written. The suite is 132 tests across 8 files.

**Still owed.** A third check of the rebound form by an independent agent,
narrow, filed as a second addendum to the verification report; the
founder's approval of the amended `SPEC.md`.
