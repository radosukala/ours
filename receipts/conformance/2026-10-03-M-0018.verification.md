   in the main checkout (its `apps/web/.env.local` may hold real keys,
   D-0021 §F):
   - **honesty and rendering:** what every page says about hosting, the
     database, the administrator and deployment, in every state; the
     README's first section; anything else that turns false at the deploy;
   - **the release and its security:** the release gate, the release step,
     its logs, `apps/web/vercel.json`, the weekly email's GET, and the
     founder script.
2. **Their tests are committed as written,** before any fix: each finding
   is a `DEFECT` test that fails on `bee6e3b`; each sound check a `closed`
   test that passes.
3. **Every finding is fixed or recorded.** A fixed `DEFECT` test is renamed
   *"fixed ("*; a test adapted to a fix says *"Changed after…"* and why.
4. **One re-check** by an agent that built and verified none of it.
5. **Every re-check finding is fixed or recorded,** and there is no further
   round.

**Classes:** every check here is `CHECKED` (a test reports). Only `R-SCOPE`
is `ENFORCED`.

### Found beside the lenses, and fixed

  in `src/web/actions.ts`, and one each in `src/core/db.ts`,
  `src/core/mail.ts` and `src/core/reports.ts`, plus `scripts/digest.ts`.
  Each now logs the error's name, as the rest of the application does.
- **`apps/web/vercel.json` dropped its install command:** Vercel's
  documentation says an override can run the oldest pnpm in its image,
  which can't read this lockfile.
